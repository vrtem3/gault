# API Gault v1

Сохранённый API версии 0.1.0 относится к отложенному кабинету. Он не развёрнут для пользователей: текущий Gault 0.1.1 работает без API, а `/api` на `gault.ru` возвращает 404. Адреса ниже описывают будущий отдельный контур, а не доступные сейчас endpoints.

Base URL: `https://account.gault.ru/api/v1`, локально `http://localhost:5174/api/v1` (через Vite-прокси). OpenAPI JSON: `GET /api/v1/openapi.json`. Endpoint загрузки файлов отсутствует.

## Формат

Все входные схемы запрещают неизвестные поля. JSON максимум 8192 байта. Изменяющие запросы требуют точного `Origin` кабинета, CSRF-cookie и `X-CSRF-Token`. Получение CSRF не требует входа:

```http
GET /api/v1/auth/csrf
```

Ответ: `{"csrf_token":"..."}`; токен хранится только в памяти клиента. Cookie HttpOnly. Вход ротирует CSRF и возвращает новое значение вместе с пользователем. Другие вкладки после 403 могут один раз обновить CSRF и повторить ранее отклонённый запрос.

Ошибки:

```json
{"error":{"code":"validation_error","message":"Проверьте заполнение полей.","fields":["email"]}}
```

Не возвращаются входные значения паролей или содержимое запроса. 401 — нет активной сессии; 403 — CSRF/закрытый доступ; 404 — объект не существует или не принадлежит пользователю; 413 — тело слишком велико; 422 — недопустимые поля; 429 — ограничение частоты (Retry-After).

## Публичные и аккаунтные маршруты

| Метод | Путь | Вход | Результат |
|---|---|---|---|
| GET | `/health` | — | Состояние API и соединения БД |
| GET | `/version` | — | Версия |
| GET | `/auth/csrf` | — | CSRF-cookie и токен |
| POST | `/auth/register` | `email`, `password` | 202 и одинаковое сообщение, письмо подтверждения |
| POST | `/auth/verify-email` | `token` | Атомарное погашение одноразового токена |
| POST | `/auth/resend-verification` | `email` | 202 без раскрытия существования email |
| POST | `/auth/login` | `email`, `password` | HttpOnly session-cookie, `user`, новый `csrf_token` |
| POST | `/auth/logout` | `{}` | Отзыв текущей сессии |
| POST | `/auth/forgot-password` | `email` | 202, одноразовое письмо при подходящем аккаунте |
| POST | `/auth/reset-password` | `token`, `password` | Новый пароль, отзыв всех сессий |
| GET | `/auth/me` | Cookie | Публичный профиль |
| GET | `/me` | Cookie | Публичный профиль |
| PATCH | `/me` | `display_name` | Обновление только собственного имени |
| POST | `/me/password` | `current_password`, `password` | Смена пароля с отзывом всех сессий |
| GET | `/me/sessions` | Cookie | Свои активные сессии без токенов, IP, User-Agent |
| DELETE | `/me/sessions/{id}` | `{}` | Отзыв собственной сессии, для чужой одинаковый 404 |
| GET | `/storage-connections` | Cookie | Только собственные записи; в MVP пустой список |

Пароль аккаунта: 15–128 Unicode-символов после NFC, без требований состава, с локальным denylist. Email уникален после приведения регистра. Техническая длина password-поля DTO ограничена 512 символами ещё до проверки политики; локальная фраза шифрования к этим схемам не относится.

Письма отправляются SMTP после фиксации токена. При сбое доставки API не раскрывает наличие адреса; можно повторить подтверждение или восстановление с учётом лимитов. Статус сбоя фиксируется без email/токена. Когда SMTP вообще не настроен, регистрация возвращает 503 независимо от адреса.

## Статистика

`POST /usage/events` — только после согласия и завершения записи, с CSRF и случайным недельным `X-Guest-Token` для гостя:

```json
{
  "operation_type": "encrypt",
  "week_key": "2026-W43",
  "guest_or_auth": "guest",
  "event_id": "6d3b1444-a584-43ab-b833-e5457da2ea12"
}
```

`operation_type`: encrypt/decrypt. Текущая сессия определяет реальную категорию; несовпадение отклоняется. Принимается только текущая неделя REPORT_TIMEZONE. Гостевой токен — непрозрачная случайная строка 32–64 символов `[A-Za-z0-9_-]`; клиент использует 32 случайных байта в hex и меняет их каждую неделю. Идентификатор события дедуплицируется. Ответ 202: `{"accepted":true}` или false для повтора.

`POST /usage/visit`, тело `{"week_key":"2026-W43"}` — отдельное добровольное посещение кабинета авторизованным пользователем. Оно не увеличивает счётчик файловых операций.

`GET /admin/usage/weekly?week=2026-W43` требует `Authorization: Bearer ...`, совпадающий с `ADMIN_API_TOKEN` (минимум 32 символа). Если конфигурация пуста — доступ закрыт. Возвращаются только числовые auth/guest агрегаты. Публичной панели статистики нет.

Rate limits: общий 300/мин; вход 20/15 мин на сетевой источник и 10/15 мин на нормализованный email; регистрация и повтор подтверждения 5/час; восстановление 5/час на источник и 3/час на email; сброс и смена пароля 10/15 мин; события 120/мин на источник и 60/мин на недельный субъект. Ключи rate limiter в памяти — HMAC, открытые IP/email в нём не сохраняются.
