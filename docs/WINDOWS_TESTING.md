# Нативная проверка A3 на Windows

Состояние: обвязка подготовлена, нативный прогон Windows ещё не выполнен. Нужны Windows 10/11 x64 с ConPTY, CPython **3.13**, Node.js 24/npm и копия проекта. Браузерные тесты используют Chromium; для реального диалога дополнительно нужен Chrome/Edge. WSL/Docker не считаются Windows-проверкой.

Команды выполняются в PowerShell из корня проекта. Используются только публичные синтетические данные. `.env`, сервер, аккаунт, SMTP и Mailpit для этой проверки не нужны; существующий рабочий `.env` не изменяется.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: --require-hashes -r frontend/scripts/requirements-windows.txt
.\.venv\Scripts\python.exe scripts/install-test-tools.py --crypto-only
$env:PYTHON = (Resolve-Path .venv\Scripts\python.exe).Path
$env:Path = (Resolve-Path .venv\Scripts).Path + [IO.Path]::PathSeparator + $env:Path
Set-Location frontend
npm ci
npx playwright install chromium
npm run test:interop
npm run test:compat
```

Установщик проверяет закреплённые SHA-256 официальных Windows ZIP age/rage, проверяет пути перед распаковкой и подготавливает одинаковые пути CLI для тестов. `pywinpty` 3.1.0 — только тестовая MIT-зависимость для Windows ConPTY, закреплённая hashes CPython 3.13 wheels; она не входит в приложение. Терминальная обвязка передаёт публичную тестовую фразу в защищённый запрос CLI, бинарный результат пишется через `-o`.

`test:compat` сам запускает шифратор на loopback:5173 в режиме `--cipher-only` и затем останавливает свой процесс. Если там уже идёт ручной тест, сначала завершите его; тесты не останавливают чужие серверы. Для гарантированно нового тестового сервера можно временно задать `$env:CI = '1'` (порт 5173 должен быть свободен), затем удалить `Remove-Item Env:CI`.

Результаты:

- `artifacts/interop-win32-x64.json`: ОС/CPU/версии, SHA-256, 30 проверок чтения старых образцов двумя CLI, отрицательные случаи и границы KDF. Статус `passed-with-browser-kdf-limitation` означает ограничение браузера, а не полную двунаправленную совместимость.
- `frontend/playwright-report/index.html`: реальный Worker, offline/PWA, старые контейнеры, матрица сбоев и приложение `native-browser-matrix` с фактическими logN входов age/rage.
- Ошибка ConPTY/установки/запуска — незавершённая проверка Windows; не заменяйте её успешным отчётом с Mac.

Известное ограничение: rage калибрует scrypt по скорости ПК. Файлы logN>18 Gault безопасно отклоняет до KDF; это ожидаемая проверка предела памяти, **не** положительная расшифровка rage → браузер. Зафиксируйте фактические параметры из отчёта. Менять KDF, бинарник или fixtures для прохождения теста нельзя.

## Ручной системный диалог

После автоматического прогона из корня запустите `.\.venv\Scripts\python.exe scripts/run-local.py --cipher-only --no-build`, откройте `http://localhost:5173` в Chrome/Edge. Возьмите небольшой несекретный файл, зашифруйте с новой фразой, сохраните с **новым** именем, расшифруйте в третий файл и сравните `Get-FileHash -Algorithm SHA256`. Повторите отмену сохранения и отмену во время обработки; исходник должен остаться прежним, ложного успеха быть не должно. Это дополнение к OPFS-автоматизации, которая системный диалог не нажимает.

Для отчёта достаточно версии ОС/браузера, результатов команд, JSON interop и отметок ручного диалога. Не отправляйте рабочий `.env`, личные файлы или настоящие фразы. После результатов обновляется статус A3 в TODO. **Тест 30 ГБ не запускать:** он не входит ни в одну команду выше.
