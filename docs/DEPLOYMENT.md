# Эксплуатация текущего Gault

## Самостоятельный шифратор

Текущий этап включает только статическую сборку шифратора на `https://gault.ru`. Её обслуживает существующий Nginx общего сервера. Python API, SQLite, SMTP и кабинет для шифрования не требуются. Стандарт age, версии криптографических зависимостей и KDF сохранены.

GitHub хранит историю исходного кода и описание приложения для пользователей. GitHub Actions отключён; проверки выполняются локально, сборки передаются непосредственно на сервер по SSH. Публикация кода не запускает тесты или деплой. Секреты и SSH-ключи в GitHub не передаются.

С 19.10.2026 корневой домен подключён: `https://gault.ru` отвечает с действительной цепочкой Let's Encrypt, HTTP перенаправляет на HTTPS. Сертификат выпущен только для `gault.ru`; пробное продление с deploy-hook прошло, отдельный таймер включён.

19.10.2026 опубликована **0.1.1** с исправлениями BOM и отмены источника, найденными расширенным fuzz. Полный build ID `0ed66d1dbdb0b87719f5a68bf5c4153350dd3ca7e0b22d5726c1a3646d7f5ed5` (в футере `0ed66d1dbdb0`). Документация и локальные проверки обновлены перед прямой передачей по SSH. Все 10 файлов новой сборки получены через публичный HTTPS и совпали по размеру и SHA-256. Два прежних хэшированных JS/Worker сохранены для открытых вкладок и проверены отдельно.

Обновлена только статика шифратора. Nginx не перезапускался; конфигурации, TLS-default, сертификат, ответы пяти соседних сайтов и состояния служб остались прежними. Закрытая резервная копия предыдущих статики и manifest сохранена. Малый автоматический Chromium/age/rage/offline-прогон новой версии прошёл; см. [TESTING.md](TESTING.md). Кабинет, backend и статистика выключены. Ручная платформенная приёмка и большие файлы остаются открытыми.

Предыдущее подключение домена выполнялось на 0.1.0, build ID `2e5ed715ebd793ec4da3feecc39537cc0dab00ee6558375c18f729808e843179`. Исторические результаты первоначальной поставки сохранены отдельно от текущего выпуска; ссылки на прежние Git-коммиты не публикуются.

| Компонент | Расположение |
|---|---|
| Статика шифратора | `/var/www/Gault/cipher` |
| Конфигурация Nginx | исходник `infra/nginx/Gault.conf`, активная ссылка `/etc/nginx/sites-enabled/zz-Gault` |
| Webroot ACME | `/var/lib/gault-acme` |
| Сертификат и ACME-аккаунт Gault | `/etc/letsencrypt-gault` |
| Рабочие файлы и журнал Certbot | `/var/lib/letsencrypt-gault`, `/var/log/letsencrypt-gault` |
| Закрытая конфигурация для будущего backend и TLS-контакта | `/etc/Gault/Gault.env`, root:root, 0600 |

SSH-ключ, SSH-конфигурация и known_hosts находятся вне репозитория. StrictHostKeyChecking не отключается. Файлы и секретные фразы пользователей на сервер не отправляются.

## DNS и HTTPS

Публичный DNS корневого домена указывает на сервер проекта. Запись `account` и сертификат поддомена пока не нужны. AAAA публикуется только при настроенном IPv6. Для ACME доступны входящие TCP 80/443; путь challenge обслуживается отдельно от HTTPS-редиректа.

Сертификат корневого домена выпущен Certbot через webroot, без nginx-плагина. Используются отдельные каталоги Gault, чтобы не менять ACME-аккаунты и сертификаты других проектов. Контакт берётся из закрытого `TLS_EMAIL`. Команда первоначального выпуска:

```bash
sudo certbot certonly --webroot -w /var/lib/gault-acme \
  --config-dir /etc/letsencrypt-gault \
  --work-dir /var/lib/letsencrypt-gault \
  --logs-dir /var/log/letsencrypt-gault \
  --cert-name gault.ru -d gault.ru \
  --email YOUR_TLS_EMAIL --agree-tos --non-interactive
```

Включён полный `infra/nginx/Gault.conf`: HTTP перенаправляет на канонический `https://gault.ru`, Nginx отдаёт только файлы шифратора; `/api` возвращает 404, проксирования backend нет. Документ запрещает соединения и iframe через `connect-src 'none'` и `frame-src 'none'`. Service worker получает отдельное разрешение только на статические ресурсы своего origin. Для уже созданной записи `account` HTTP возвращает 404.

На общем сервере Gault подключён поздним include `sites-enabled/zz-Gault`: это сохраняет прежний TLS-vhost по умолчанию. Явный HTTP default остаётся у Gault. Перед каждым graceful reload выполняется `nginx -t`; действующие сайты не останавливаются и их конфигурации не заменяются. После подключения совпали контрольные суммы чужих конфигураций, ответы пяти сайтов и отпечаток прежнего TLS-default.

`Gault-tls-renew.timer` активен и включён в автозапуск. Он проверяет необходимость продления дважды в сутки со случайной задержкой до часа. Прогон `certbot renew --dry-run --run-deploy-hooks` прошёл с теми же отдельными каталогами и `UMask=0077`; рабочий сертификат при этом не заменялся. Deploy-hook выполняет `nginx -t` и graceful reload только после успешного продления. Текущий сертификат действует до 17.01.2027 UTC.

```bash
sudo nginx -t
sudo systemctl status nginx
sudo systemctl status Gault-tls-renew.timer
```

## Обновление и проверка поставки

Сборка по умолчанию создаёт только `frontend/dist` и его SHA256SUMS. Для production используется публичный origin `https://gault.ru`; закрытые значения в сборку не передаются. Перед заменой серверных файлов проверяются хэши и состав пакета: без env, ключей, БД, локальных отчётов и статики кабинета. Source manifest должен различать исходный commit и локальные изменения сборки.

При упаковке воспроизводимого архива с `mtime=0` после извлечения задаётся фактическое время установки статических файлов. Иначе Nginx может выдавать одинаковые ETag для разных ревизий одинакового размера. HTML, SW и метаданные требуют перепроверки кэша (`no-cache`), ресурсы с хэшем в имени имеют `immutable`; байты файлов и SHA256SUMS от установки времени не меняются. Предыдущие собственные файлы и manifest сохраняются в закрытой резервной копии для отката.

При обновлении 0.1.1 выполнен предварительно проверенный атомарный обмен собственных каталогов на сервере (`renameat2`, `RENAME_EXCHANGE`), без перезапуска Nginx. Хэшированные JS/Worker предыдущей сборки временно сохранены рядом с новыми ресурсами для уже открытых вкладок; они перечислены отдельно как `retainedAssets` в закрытом deployment manifest. SHA256SUMS новой сборки описывает только её собственные файлы. Перед переключением и после него проверены конфигурации и ответы соседних сайтов, TLS-default и состояние отложенных служб.

После обновления проверяются HTTP/HTTPS, CSP, типы ресурсов, `/api` → 404, отсутствие кабинетных ссылок и iframe, офлайн-кэш, малый roundtrip и SHA-256 восстановленного файла. Криптооперации выполняются без сетевых запросов, включая период после закрытия выходного файла. Отложенные платформы и размеры не считаются проверенными.

Существующая PWA ожидает закрытия старых вкладок; принудительное обновление во время шифрования не выполняется. Подготовленная старая вкладка может продолжать использовать прежнюю версию до закрытия.

## Отложенный кабинет

Исходники и окружение backend сохранены в `/opt/Gault`, его данные — в закрытом `/var/lib/Gault`. Статика кабинета убрана из публичного webroot и сохранена в `/opt/Gault/deferred/account-static`. `Gault.service`, `Gault-privacy-cleanup.timer` и `Gault-weekly-report.timer` остановлены и отключены; порт `127.0.0.1:18000` закрыт. Другие приложения сервера не менялись.

Перед отключением очистки подтверждено отсутствие краткоживущих идентификаторов статистики. БД сохранена с правами 0600, каталогом 0700 и отдельной SQLite Backup API-копией; `integrity_check` копии прошёл. Восстановление на целевом сервере ещё требует отдельного испытания перед возвращением кабинета. Production-конфигурация остаётся закрытой, SMTP не подключён.

Возвращение кабинета — будущий этап после приёмки криптографического ядра. Тогда отдельно проверяются API, миграции, авторизация/CSRF, почта и backup/restore, подключаются DNS/HTTPS `account.gault.ru`, затем включаются нужные службы. Сохранённые systemd/Docker-конфигурации сами по себе не разрешают запуск этого контура сейчас.

Тест 30 ГБ остаётся отложенным пользователем. На текущем ПК его не запускать; малые проверки не подтверждают поддержку такого объёма.
