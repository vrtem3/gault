# Архитектура Gault 0.1.1

Текущий этап — самостоятельный локальный шифратор и его криптографическая приёмка. Кабинет, API, почта, статистика и новые пользовательские функции отложены по решению владельца.

Профиль поддерживаемых контейнеров и порядок изменения криптозависимостей зафиксированы в [COMPATIBILITY.md](COMPATIBILITY.md). Версия формата age v1 не меняется из-за обновления CLI или номера редакции спецификации.

## Текущий контур

```text
gault.ru
  frontend/dist/
  React + Typage Worker
  File → stream → Worker → disk
  PWA cache, connect-src 'none', frame-src 'none'
```

Локальный адрес — `localhost:5173`. Обычный launcher и стандартная сборка запускают только шифратор. На общем сервере существующий Nginx обслуживает его статику; Python/API, БД и SMTP для этого не требуются. Маршруты `/api` возвращают 404. Серверная эксплуатация описана в [DEPLOYMENT.md](DEPLOYMENT.md).

GitHub используется для хранения состояния кода и пользовательского описания. CI/CD через GitHub отсутствует: проверки запускаются локально, деплой выполняется напрямую на сервер по SSH.

Версия шифратора берётся из `frontend/package.json` и используется в интерфейсе и `build-info.json`; build ID различает конкретные сборки. Версия 0.1.1 включает исправления адаптера и надёжности, формат age v1 и scrypt logN=18 сохранены. Метаданные неиспользуемого API остаются на 0.1.0 до возвращения этого отдельного компонента.

Код кабинета сохранён в `frontend/account/src`, серверная часть — в `backend/`. Они исключены из текущего запуска и публикации. Контейнерный вариант и `build:account` сохранены для будущего этапа; стандартный `build` их не запускает. Публичная сборка не импортирует код кабинета, отправку статистики или SDK облаков.

## Потоки

1. При открытии формы загружается ещё не содержащий секретов Worker.
2. Нажатие пользователя открывает диалог сохранения; до начала обработки проверяются ограничения устройства и имя результата.
3. Worker читает `File.stream()`, вызывает стандартный Streaming API `age-encryption` 0.3.1 и отправляет по одному выходному блоку.
4. Основной поток записывает блок, затем подтверждает приём Worker. Очередь не накапливает весь файл.
5. Только после последнего блока и успешного `close()` показывается «Файл записан». Worker завершается, поля фразы очищаются.
6. Отмена немедленно завершает Worker и вызывает `abort()` записи. До close непроверенная расшифровка не выдаётся за успешную.

Полный `arrayBuffer()` применяется только в малых тестах и для первых 8192 байтов публичного заголовка при предохранительной проверке. В основной обработке целого файла такой операции нет. В явно ограниченном fallback до 100 МБ разрешено накопление результата в RAM; там UI честно сообщает лишь о готовности скачивания.

Сравнение имён назначения и исходника консервативное: NFC + регистронезависимое сравнение. Input File не предоставляет исходный файловый handle, поэтому нельзя гарантировать обнаружение всех алиасов файловой системы; сохраняйте результат с новым именем.

## PWA и CSP

Сборка генерирует `sw.js` со списком всех JS/CSS/Worker/manifest/лицензий. Готовность офлайн появляется только после проверки каждого элемента кэша. Кэш хранит исключительно публичные статические ресурсы. `ignoreVary` используется для них, чтобы `Vary: Origin` preview-сервера не нарушал офлайн-выдачу; API на cipher-origin отсутствует.

У документа и crypto Worker `connect-src 'none'`; документ дополнительно запрещает iframe через `frame-src 'none'`. Только service worker получает `connect-src 'self'`, необходимый для начального precache. Новая версия активируется после закрытия всех вкладок старой версии; принудительного обновления посреди шифрования нет. Футер показывает отпечаток build-входов/публичных параметров/Node; уведомление ожидающего SW даёт подтверждение и инструкции закрытия вкладок. Ошибка precache не удаляет рабочий кэш. Подробные границы доверия: [THREAT_MODEL.md](THREAT_MODEL.md).

## Отложенные кабинет и статистика

Текущая сборка не отправляет события использования: вызов статистики из формы удалён, переключателя согласия нет, iframe запрещены CSP. Даже сохранённое в старой версии согласие не включает отправку. В браузерных проверках контролируется отсутствие запросов и iframe до, во время и после операций.

Сохранённая заготовка кабинета использует отдельный origin `account.gault.ru` и собственный API; возвращать его на origin шифратора не планируется. Для текущего шифратора DNS-запись и сертификат поддомена не нужны. Служба API и её таймеры на сервере отключены; закрытая БД и её резервная копия сохранены вне публичной статики.

Будущий telemetry bridge и его helpers сохранены в исходниках как часть отложенного контура, но не входят в публичный JS. Их включение, как и подключение аккаунтов, требует отдельной проверки безопасности и приёмки после криптографического этапа.

## Backend и общие функции — отложенный контур

Ниже описан сохранённый код; он не используется текущим шифратором и не запускается в production.

`app/basic_functions.py` содержит переиспользуемые функции БД, безопасности, SMTP и агрегирования. `app/api` — маршруты, `models` — таблицы, `schemas` — строгие DTO. Токены сессий и email хранятся как HMAC-SHA256; исходные случайные значения живут только в памяти запроса/cookie/письме по назначению.

Короткоживущие отпечатки статистики очищаются при приёме событий, еженедельном job и отдельным режимом `--cleanup-only` каждые 15 минут внешним systemd timer (независимо от SMTP и новых визитов). Счётчик уникальных пользователей сохранён в агрегатах, поэтому удаление TTL-таблиц не уничтожает исторические числовые сводки.

У SQLite включены foreign_keys, WAL и busy_timeout. Миграции не создаются автоматически при запуске приложения: выполняется только заранее зафиксированный `alembic upgrade head`. Два одновременных Argon2 вычисления ограничивают расход серверной памяти. Rate limit рассчитан на один worker и сбрасывается при перезапуске; сведения не являются платёжной или аудиторской системой.

## Масштабирование

БД должна находиться на локальном диске, не NFS. Несколько API-инстансов не поддерживаются этим MVP. При частой конкуренции записей или необходимости нескольких backend-инстансов отдельно проектируется переход на PostgreSQL. SQLite-специфичные настройки и операции идемпотентной вставки локализованы в общих функциях и ядре БД.

## Испытательная обвязка A1–A5

По умолчанию launcher запускает только статическую cipher-сборку на loopback:5173, не требует API/SMTP/БД и не выполняет миграции. `--cipher-only` сохранён для совместимости команд нативной проверки Windows/macOS. Полный отложенный контур доступен явно через `--with-account` для будущей разработки. Стандартные Playwright-профили исключают `account.spec.ts`. Для корректной остановки дочерних групп Playwright на POSIX использует graceful SIGTERM; Windows использует дерево процессов.

Контейнеры прошлых версий лежат в `frontend/tests/fixtures/compatibility/`; manifest/хэши фиксируются, Git не меняет LF/CRLF. CLI-обвязка пишет бинарный результат через `-o`, парольный запрос обслуживает POSIX PTY или тестовый Windows ConPTY (pywinpty). Приложение от pywinpty не зависит.

Измеритель `test:streaming` создаёт только собственные синтетические данные и пишет оба результата в OPFS настоящими FileSystemWritableFileStream. Хэшируется весь записанный файл ограниченными срезами через локальный драйвер, без нового backend endpoint. Ресурсный отчёт не доказывает поддержку размеров, которые не испытывались. Испытательная обвязка не подменяет производственный Worker; криптографический алгоритм и KDF сохранены.
