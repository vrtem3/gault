# Контракт совместимости и выпуск Gault

## Поддерживаемый профиль

Версия шифратора 0.1.1 сохраняет профиль 0.1.0; исправления проверки заголовка и отмены чтения не меняют контейнер или KDF. Неизменяемые файлы 0.1.0 используются для регрессии и не пересоздаются при смене номера приложения.

Формат файла — **age format v1**, независимо от номера релиза Gault или программы age/rage. Источник спецификации — [C2SP age](https://c2sp.org/age); при проверке 19.10.2026 он указывает редакцию документа `v1.1.0`, которая по-прежнему описывает формат файлов `v1`.

Gault создаёт бинарный `.age` с одной парольной scrypt stanza через `age-encryption`. Шифрование: logN=18, r=8, p=1. Чтение в браузере: одна scrypt stanza, logN от 1 до 18, публичный заголовок до 8192 байтов. Верхний предел защищает память браузера. Действительность заголовка, MAC и всех блоков проверяет библиотека, а не предварительный фильтр Gault. Пробелы/Unicode фразы не нормализуются.

ASCII armor, recipient/SSH/плагинные ключи, несколько получателей и более дорогой KDF не входят в браузерный профиль. Для них пользователь использует независимые CLI. Это границы MVP, а не новый вариант формата age. Контейнер не требует аккаунта, backend или сети; серверных ключей для него нет.

Обязательные инварианты: потоковый File → Worker → sink, один неподтверждённый выходной блок; успех записи только после полного чтения, проверки библиотекой и close. Отмена/ошибка не превращаются в успех. RAM-fallback и смартфоны ограничены 100 МБ. Обновления PWA не вызывают skipWaiting и не заменяют код в работающей вкладке.

## Зафиксированная база

На 19.10.2026 проверены официальные страницы релизов: [Typage 0.3.1](https://github.com/FiloSottile/typage/releases/tag/v0.3.1), [age 1.3.2](https://github.com/FiloSottile/age/releases/tag/v1.3.2), [rage 0.12.1](https://github.com/str4d/rage/releases/tag/v0.12.1). Версии совпадают с закреплённой базой проекта; обновление не требуется по одному лишь номеру спецификации C2SP.

`frontend/package-lock.json` фиксирует npm-дерево, `scripts/tools-lock.json` — официальные CLI и SHA-256 архивов. В fixtures сохраняется происхождение конкретного контейнера. Локальная проверка на macOS не является подтверждением Windows; результаты платформ указываются отдельно в [TESTING.md](TESTING.md).

Обнаруженная граница: rage 0.12.1 калибрует KDF под машину; контрольные файлы на этом Mac получили logN=19–20. Они восстанавливаются CLI, но браузер правильно отказывает по пределу памяти. Поэтому нельзя объявлять безусловное rage → Gault для любых default-параметров. [Разбор памяти и безопасное решение](RAGE_COMPATIBILITY.md): сохранить обычный предел 18, для 19–20 использовать официальный CLI с исходным KDF. Отдельный режим чтения на ПК предложен для будущей реализации после ресурсных испытаний; он ещё не реализован. Параметры и контрольные файлы ради зелёного теста не меняются.

На 19.10.2026 просмотрены опубликованные advisories: [age GHSA-32gq-x56h-299c](https://github.com/FiloSottile/age/security/advisories/GHSA-32gq-x56h-299c) исправлен с 1.2.1; [rage GHSA-4fg7-vxc8-qx5w](https://github.com/str4d/rage/security/advisories/GHSA-4fg7-vxc8-qx5w) — в исправленных ветках, включая 0.11.1. Закреплённые CLI новее этих исправлений; данная проблема касается имён плагинов, которые браузерный профиль не использует. Это проверка конкретных опубликованных сообщений, а не независимый аудит.

## Чек-лист перед каждым релизом и изменением криптозависимостей

1. Сверить [C2SP](https://c2sp.org/age), стабильные [Typage](https://github.com/FiloSottile/typage/releases), [age](https://github.com/FiloSottile/age/releases), [rage](https://github.com/str4d/rage/releases). Прочитать release notes и изменения streaming/passphrase/scrypt. Номер CLI не меняет формат контейнера.
2. Проверить advisories [Typage](https://github.com/FiloSottile/typage/security/advisories), [age](https://github.com/FiloSottile/age/security/advisories), [rage](https://github.com/str4d/rage/security/advisories) и `npm audit --omit=dev`. Отсутствие опубликованного advisory не является доказательством отсутствия уязвимостей. При новом advisory проверку выполнить вне обычного цикла релиза.
3. Сначала прочитать неизменяемые fixtures прошлых релизов, проверить SHA-256 самих образцов и восстановленных данных. Сохранять старые коллекции; новые образцы добавлять под новой версией. Не перегенерировать их тестами.
4. Выполнить unit, реальный browser Worker, четыре направления Gault ↔ age/rage на Windows/macOS, негативные случаи и матрицу сбоев A4. Отдельно проверить офлайн и установку новой PWA во время операции. Команды и ручные пункты — в [TESTING.md](TESTING.md).
5. Если новый CLI изменил default KDF, отдельно проверить его фактический заголовок и затраты памяти. Не ослаблять KDF, не снимать защитный предел и не обновлять библиотеку без регрессии ради прохождения теста.
6. Только затем менять точные версии/lockfile и проверенные SHA-256. Повторить проверки на кандидатной сборке, лицензии и хэши релиза; записать версии, ОС, браузер, хэши и оставшиеся ограничения в отчёт.
7. Не выполнять автоматическое обновление приложения/зависимостей внутри операции. Сервер может предложить новую PWA, но она ожидает закрытия старых вкладок. Сохранить подготовленной версии возможность завершить обработку офлайн.

Испытание ≥30 ГБ остаётся отдельным незакрытым пунктом A6: пользователь его отложил. Оно не запускается этим чек-листом или обычными тестами без нового прямого запроса. Успехи на малых файлах не разрешают обещать подтверждённые 30 ГБ.
