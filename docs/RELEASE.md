# Локальная проверка перед обновлением сайта

Gault — некоммерческий сервис на gault.ru. GitHub хранит открытые исходники для ознакомления с реализацией и пользовательское описание. Эта процедура предназначена для внутренней проверки качества перед обновлением сайта. Она не включает Actions, CI/CD, автоматический push, деплой или публикацию Issues. Ключи, `.env`, локальный TODO и результаты проверок не входят в публичный артефакт.

## Зафиксированный профиль

`frontend/release-profile.json`: Node **24.19.0**, npm **11.17.0**, lockfile v3, публичные production-параметры. npm 11.17.0 соответствует официальной поставке Node 24.19.0. Минимальная совместимость приложения с Node и профиль проверенного выпуска — разные ограничения. Runtime-зависимости и native build-пакеты устанавливаются по `package-lock.json`; для чистого окружения применяйте `npm ci` указанной версией npm. Криптозависимости не обновляются этой процедурой.

Сборка выполняется с `TZ=UTC`, `LANG=C`, `LC_ALL=C` и явными публичными параметрами. Секретные env-переменные в Vite-конфигурацию не передаются; разрешены только заранее перечисленные PUBLIC-поля. В коде сортировки нет зависимости от системной локали, пути SHA256SUMS используют прямые слеши на всех ОС; Tailwind сканирует только указанные TS/TSX-исходники, а не соседние отчёты/сборки.

## Команды

Из `frontend` после подготовки зависимостей и тестовых age/rage:

```bash
npm run check:release
```

Или тем же Node без npm CLI:

```bash
node scripts/release-check.mjs
```

Последовательно проверяются: typecheck; unit и ограниченный fuzz; сборка и лицензии; SHA256SUMS и allowlist статики; две изолированные сборки и сравнение с основной; малый Chromium-профиль с trace; независимые age/rage; текущие advisories npm. Локальный `artifacts/release-check.json` содержит статусы/длительности. Любая ошибка завершает команду неуспешно; отсутствие доступа к advisory API не трактуется как отсутствие уязвимостей.

Специальный lint-инструмент в проекте пока не настроен: TypeScript включает strict/noUnusedLocals/noUnusedParameters; whitespace дополнительно проверяется `git diff --check`. Выбор отдельных lint-правил остаётся задачей контроля качества кодовой базы, новые зависимости ради него не добавлялись.

Проверка advisories отправляет в **официальный npm registry** только публичные имена и версии из lock-файла, включая dev/optional пакеты. Исходники, `.env`, файлы и фразы пользователей не отправляются. Результат — снимок известных advisories на дату запроса, не аудит кода.

Браузерные результаты каждого выпуска записываются в отдельный `artifacts/e2e-release-<id>`, чтобы один запуск не удалял trace другого. Все операции используют малые синтетические данные. Большой скрипт не вызывается; `GAULT_ALLOW_LARGE_TEST` принудительно выключен. Ручные диалоги/Windows/смартфоны, публичный HTTPS и большие архивы эта команда не принимает.

Отдельные проверки:

```bash
npm run test:fuzz
npm run test:repro
npm run check:artifact
npm run check:dependencies
```

`test:repro` создаёт две новые копии только build-входов в `.tools`, без `.env`, истории Git и пользовательских файлов. В обеих используются **общие уже установленные node_modules**. Их статика сравнивается побайтово, временные деревья удаляются, отчёт/хэши остаются в `artifacts/reproducibility.json`. Выпускная команда дополнительно сравнивает их с основной `dist`. Это проверка детерминизма на текущем Mac; независимая установка на другом ПК и идентичность Windows/macOS ею не подтверждаются.

Независимая сборка на другом ПК, подписи публичных релизов и дополнительные материалы для доказательства соответствия сайта исходникам в текущий план не входят. Эти проверки не заявляются выполненными. Существующие локальные проверки сборки, контрольных сумм поставки и исключения секретов сохраняются.

## Что означают идентификаторы

Версия шифратора задаётся в `frontend/package.json`; корневые записи `package-lock.json` должны ей соответствовать. Интерфейс и `build-info.json` используют это же значение. Для выпуска исправлений безопасности и надёжности номер patch повышается: текущий выпуск — **0.1.1**. Изменение версии приложения не меняет формат age v1, параметры KDF или неизменяемые образцы 0.1.0. Версия отложенного API ведётся отдельно.

Футер и `build-info.json` также содержат SHA-256 build-входов, публичных параметров и Node. `SHA256SUMS` содержит контрольную сумму **каждого фактического файла статики**; сам список не включается в себя. Изменение публичного ресурса с прежним именем тоже меняет ID кэша. Разные проверочные сборки одной версии могут иметь разные build ID; запись в CHANGELOG описывает подготовленный выпуск, а [DEPLOYMENT.md](DEPLOYMENT.md) — фактически опубликованную сборку.

SHA256SUMS позволяет сверить содержимое, если эталон уже получен по доверенному каналу. Хэш или подпись, загруженные с того же скомпрометированного сайта, не удостоверяют первую загрузку HTML/JS. Сам футер также может быть подменён. Не объявляйте совпадение сборок криптографическим аудитом или доказательством того, какой код выполнил конкретный браузер.
